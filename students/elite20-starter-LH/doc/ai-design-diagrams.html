专业级三层架构设计 | 表示层 → 业务逻辑层 → 数据访问层

1. 系统架构图

本系统采用经典的三层架构设计，清晰分离表示层、业务逻辑层和数据访问层，实现高内聚低耦合的软件设计原则。

3. 组件交互流程

📋 完整调用流程

1. 用户输入 → 用户在表示层输入代码和 API Key
2. 服务检测 → 业务逻辑层调用 detectService() 识别服务类型
3. 请求构造 → 构建完整的 Prompt 和 HTTP 请求参数
4. API 调用 → 业务逻辑层调用 callAI() 发起请求
5. 数据访问 → 数据访问层根据服务类型调用对应 AI 服务
6. 响应处理 → 解析响应并转换为统一格式
7. 结果展示 → 表示层渲染 Markdown 结果

3.1 服务检测流程

业务逻辑层通过 detectService() 函数自动检测 API Key 所属服务：

  • sk- 开头且长度 > 50 → 硅基流动 (SiliconFlow)
  • sk- 开头且长度 ≤ 50 → OpenAI 兼容服务
  • 包含 ":" 分隔符 → 百度千帆
  • 其他格式 → 豆包 (Doubao)

3.2 请求处理流程

核心调用函数 callAI() 的处理逻辑：

  1. 清理和验证 API Key（sanitizeApiKey()）
  2. 根据服务类型获取配置（AI_SERVICES）
  3. 构造包含代码分析提示的完整 Prompt
  4. 设置超时机制（timeoutPromise()）
  5. 发送 HTTP POST 请求并处理响应
  6. 调用 parseResponse() 提取结果

5. 架构设计原则

  • 分层解耦：各层职责明确，通过接口交互，降低耦合度
  • 单一职责：每个组件只负责一个功能，便于维护和测试
  • 依赖倒置：高层模块不依赖低层模块，都依赖抽象接口
  • 开闭原则：对扩展开放，对修改封闭
  • 降级机制：当 AI 服务不可用时，自动切换到本地分析引擎
